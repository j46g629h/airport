| `admin-list.html` ＋ `js/admin-list.js` | 手機卡片／桌機表格，**同一份 HTML** 靠 CSS 切換 |

**篩選刻意分兩層：**

| 層 | 條件 | 打不打 API |
|---|---|---|
| 第一層 | 日期區間（快捷：本週／未來 14 天／本月／過去 30 天／全部） | **打**，一趟 3~8 秒 |
| 第二層 | 關鍵字（姓名・中文名・email・聯絡人信箱・房號）、接／送、狀態（可複選）、廠別、部門、上車地點、航班號、只看有需求的 | **不打**，打字就即時反應 |

排序：日期（預設）／姓名／航班號／最後更新。

幾個決定與理由：

- **不快取查詢結果。** `_INDEX` 本來就有 5 分鐘落差，前端再壓一層快取，
  管理者剛在 Sheet 上改完、回來看還是舊的，他會判定系統壞了。
  所以只存**篩選條件**（`sessionStorage`），資料一律重抓，
  畫面下方標明「資料更新於幾點」與那 5 分鐘的落差。
- **待定的行程管理端看得到日期**（使用者端相反，那是刻意的）——
  管理者就是那個要去把日期敲定的人，看不到原訂日期他無從追起。
- **同一天之內，沒有出廠時間的排最後**，不是最前面。
  空字串在字串比較裡最小，不處理的話「時間不明」的那幾筆會頂在當天最上面，
  真正要排的車全被擠下去。（前後端兩邊的排序規則要一致，不然換排序再換回來順序會變）
- **出廠時間跟航班同一天就只顯示時間**，跨天才印日期——
  跟 Sheet 上那一欄同一個規則。同一天還印一次完整日期的話，
  凌晨航班（車前一天晚上就出發）那幾筆就不顯眼了，而那正是最需要一眼看出來的。
- **一次最多回 800 筆**（超過就取離今天最近的，並在畫面上警告），前端一次畫 50 筆。
  這個上限不是為了後端，是為了工廠配的中低階手機——
  幾百個 `<tr>` 一次塞進 DOM 會卡到看起來像當機。
- 廠別／部門／上車地點的下拉**從回傳的資料萃取**，不另外讀 `PENGATURAN`——
  省一趟 API，而且選單上出現的每個選項一定篩得到東西（不會選了之後一片空白）。
- 「本週」是**週二～週一**，跟 Sheet 的週分頁同一個切法（`WEEK_START_DOW = 2`）。
- 「今天」用 **UTC+7 換算出雅加達的今天**，不是裝置的今天。
  台灣的手機比雅加達快一小時，台北 00:30 時雅加達還在前一天——
  直接用裝置日期的話，那一個小時裡按「本週」會整段位移一天，而且畫面上看不出哪裡不對。

品牌識別沒有損失——favicon 在每一頁的 `<head>` 裡。

**修掉兩個同源的頂列 bug**（使用者回報：手機上看不到標題、語言切換跑到左邊）：

```css
@media screen and (max-width: 420px) {
  .topbar .brand { display: none; }   /* ← 首頁沒有返回鍵，一藏就什麼都不剩 */
  .backbtn { margin-right: auto; }    /* ← 首頁沒有 .backbtn，沒人推語言切換 */
}
```

兩個都源自同一個毛病：**版面靠「隔壁有某個元素」成立**。那個元素不存在或被隱藏，
版面就散掉，而且不會有任何錯誤訊息。改成語言切換自己 `margin-left: auto`，
對任何頁面都成立。窄螢幕的取捨順序改為：標題永遠顯示 →
不夠時犧牲返回鍵的**文字**（箭頭留著，仍是 48px 的按鈕）。

**圖示三件組**（照員工餐廳的三層規則）：

| 檔案 | 內容 | 為什麼 |
|---|---|---|
| `favicon.svg` | PCI | 分頁實際顯示 16px，實測三個字母已經是極限 |
| `apple-touch-icon.png` | PCI GA，180px | 空間夠，放完整標誌。⚠️ **iOS 不吃 SVG**，一定要 PNG |
| `manifest.json` | 主畫面名稱「Antar Jemput」 | 補上之後可以「加到主畫面」，開起來像 app |

⚠️ 字母全部是**幾何路徑**，不用任何字型。用 `<text>` + font-family 的話，
SVG 會拿「觀看者自己電腦上的字型」來畫，同一個圖示在 Windows／iPhone／Android 會長得不一樣。
⚠️ PNG 是**直角滿版**的：iOS 與 Android 會自己套圓角遮罩，圖檔自己再帶圓角會變成
「圓角疊圓角」，四個角出現缺口。

⚠️ **`manifest.json` 是 JSON，不能寫註解**，所以兩個決定記在這裡：
`display: standalone`（開起來沒有網址列，像 app）；
`theme_color` / `background_color` 都是 `#EFEFED`，必須跟 `css/style.css` 的 `--bg` 一致，
不然手機頂端會有一條白條。

**RWD 防禦與自動檢查**：見 `CLAUDE.md` 設計約定第 9 條。
自動檢查逼出三個**既有**的版面問題（不是這一版造成的）：

| 問題 | 症狀 | 原因 |
|---|---|---|
| `.kv dd` 沒有 `min-width: 0` | 一個長 email 把「值」那一欄從 200px 撐到 490px，手機上詳細資料要左右滑 | grid 子元素預設不縮到內容以下 |
| `.dtable td` 沒有 `flex-wrap` | 卡片模式下姓名一長，右邊的廠別標籤被推出畫面**消失** | 標籤自己 `nowrap`，縮不了 |
| `.lang button` 只有 36px 高 | 5 個頁面每一頁都低於專案自己訂的 `--tap-min`（48px） | 沿用預設值沒對照過標準 |

### 首頁說明與閒置自動登出 ✅（v2.8）

**一、首頁「查詢我的行程」加上一般使用者的說明。**

原本只有一行「輸入電子郵件，查看自己的接送安排」。來這個網站的人有九成以上
是一般同仁，而且多半是第一次來、沒有人教過他——所以這一格的說明比管理者那一格長，
是刻意的（管理者只有 2~3 位，是受過交代的）。

現在寫三件做得到的事 ＋ 一條限制：

| | 內容 |
|---|---|
| 用 email 查 | 自己的接送安排，以及共用同一個信箱的家屬 |
| 用日期／航班號查 | 跟你同一班飛機的還有誰 |
| 查得到什麼 | 日期、出廠時間、上車地點、航班號 |
| ⚠️ 限制 | **只查得到今天以後的行程**，已經過去的請洽總務 |

⚠️ 說明**只寫做得到的事**。「對自己那一筆提出需求」規格書裡有、但介面還沒做
（目前只看得到管理者填的需求），所以這裡不能寫——寫了就會有人在頁面上找那個按鈕，
找不到就打電話來問。

⚠️ 那條限制用分隔線跟上面的清單分開、顏色也不同。混在清單裡的話會被當成
第四項功能讀過去。

**二、管理者閒置 1 小時自動登出。**

**先前完全沒有這個機制。** 原本的規則是「登入後 6 小時到期」——不管有沒有在操作。
分頁一直開著沒關，在工廠的共用電腦上就是一個洞。

改成**閒置**逾時：算的是「距離上一次呼叫後端有多久」，不是「登入了多久」。
連續工作一整天不會被踢出去，停手一小時就會。

三層，少一層就會壞：

| 層 | 檔案 | 做什麼 |
|---|---|---|
| 後端（唯一真正的把關） | `gas/Auth.js` `withAuth()` | 憑證裡存 `seen`，超過 `AUTH.IDLE_TTL` 就**當場刪掉**並回 `SESSION_IDLE` |
| 前端（體驗） | `js/admin-session.js` `startIdleWatch()` | 盯著點擊／打字，到期前 5 分鐘跳警告條，到期自己回登入頁 |
| 登入頁 | `js/admin-login.js` `showBounceReason()` | 用 `?idle=1` 講出「為什麼會回到這一頁」 |

**五個一定要注意的地方**（每一個都對應一種安靜的失效）：

| # | 事情 | 少了會怎樣 |
|---|---|---|
| 1 | 閒置檢查要排在**權限檢查之前** | 到期的憑證打超管 API 會拿到 `FORBIDDEN`，使用者以為權限被拿掉了，實際上只是該重新登入 |
| 2 | 到期要**當場刪掉憑證**，不能只回錯誤 | 它會一直躺到 `TOKEN_TTL`（8 小時），那段期間仍然是一支「存在的」憑證 |
| 3 | `TOKEN_TTL` 一定要 **>** `IDLE_TTL` | 反過來的話它先到期，使用者在還沒閒置滿一小時時就被登出，畫面上看不出為什麼 |
| 4 | 舊憑證（沒有 `seen`）**不判定為到期** | 一按下重新部署，所有正在使用的人會同時被登出 |
| 5 | 分鐘數由後端經 `idle_minutes` 傳給前端 | 兩邊各寫一個數字，改了一邊忘了另一邊 → 「畫面說還有 10 分鐘，按下去卻說登入已過期」 |

**兩個時鐘要對得起來。** 前端算的是「有沒有動手」，後端算的是「有沒有呼叫 API」——
這兩件事不一樣：列表頁的篩選是純前端的，可以連按半小時而一次 API 都沒打。
所以前端在「人還在動、但 API 很久沒打」時會補一次無聲的續期。

**踩到一個坑（記進 CLAUDE.md）：**
全頁監聽 `pointerdown` 當作「有動作」，處理函式把警告條 `remove()` 掉——
手指按在「繼續使用」上的那一瞬間，按鈕就從 DOM 消失了，
**等 click 要送達時已經沒有那顆按鈕**，於是它永遠按不到。
而畫面看起來完全正常（警告條確實收起來了），只有「向後端續期」安靜地不發生。
兩個作法都做了：全頁監聽跳過警告條那一塊，收起來改用 `hidden` 不用 `remove()`。

**驗證**：`test-idle.js` 28 項（後端，用假時鐘推時間，不是真的等一小時）、
`test-idle-ui.js` 24 項（前端，真的按下去看畫面）。

### 手機版操作介面的七項調整 ✅（v2.7）

使用者在 iPhone 15 Pro／Safari 上實際操作後回報的七件事，全部是**手機環境才看得到**的問題。

| # | 回報 | 做法 |
|---|---|---|
| 1 | 查 email 的說明看不懂要打多少 | 改成「至少打到 @ 前面那一段（例如 linda.lim）」，並說明共用信箱的家屬會一起顯示 |
| 2 | 不知道航班號要不要空格、分不分大小寫 | 說明補上「英文與數字不需空格，大小寫不拘」 |
| 3 | 管理頁之間要按上一頁才能換 | 頂列下面加一條切換列（班表列表／帳號管理） |
| 4 | 日期區間的「起／迄」撐破卡片 | `input[type="date"]` 加 `-webkit-appearance: none` |
| 5 | 快捷區間 5 顆按鈕排得參差不齊 | 窄螢幕改 3 欄格線 → 3＋2 兩行，等寬等高 |
| 6 | 狀態按鈕同上 | 同一條格線 → 3＋3 兩行 |
| 7 | 「過去 30 天」用不到那麼久 | 改成「過去 14 天」 |

**第 4 項：Chromium 重現不出來，只有 iOS 會壞。**
`input[type="date"]` 在 iOS Safari 上是**原生控制項**，它有自己的固有寬度，
`width: 100%` 對它無效——所以它會用自己的寬度撐出卡片外，文字還被置中。
`-webkit-appearance: none` 是把它降級成一般輸入框、讓 CSS 的寬度重新生效的唯一開關
（另外補 `min-width: 0` 與 `text-align: left`，前者讓它在 flex 裡縮得下去）。
⚠️ 開發端的自動版面檢查跑的是 Chromium，**這一類問題檢查不出來**，
所以新增的 `dateBad` 只驗「有沒有寫 `appearance: none`」＋「有沒有超出容器」，
不假裝能量到 iOS 的行為。

**第 5、6 項踩到一個 CSS 的坑（記下來）：**
`.chips` 的 3 欄格線一開始寫進了檔案前段（頁首那一區）的 420px 區塊裡，
而基本宣告 `.chips { display: flex }` 在檔案後段。
兩邊選擇器都是 `.chips`、**權重完全相同**，而
**媒體查詢不會增加權重**——所以權重相同時是「檔案後面的贏」，
`display: flex` 把 `display: grid` 蓋掉了。畫面上完全正常、也不會有任何錯誤，
只是「新規則沒生效」。

> ⚠️ **媒體查詢裡的規則要放在它想覆蓋的那條基本宣告之後。**
> 這條坑的特徵是「CSS 看起來完全正確，但就是沒作用」。

為什麼是 3 欄（實測，不是隨便挑）：320px 螢幕扣掉內距約剩 254px，3 欄各 79px；
印尼文最長的「14 hari ke depan」折成兩行放得下，4 欄就會擠爆。
格線的另一個好處是**同列等寬等高**（flex 做不到），所以文字長短不一時邊界仍然對齊。

**順手修的一項（使用者沒點名，但他的描述透露了它）：**
使用者把狀態說成「7 個按鈕」，實際上狀態只有 6 顆——第 7 顆是
`#toggleMore`「更多篩選」，它跟狀態用同一個 `.chip` 樣式、又緊貼在下面，
所以**被當成狀態的一部分**。拉開間距、窄螢幕拉成整條，一眼就分得出是兩件事。

⚠️ 切換列的 id 是 `pageNav` 不是 `adminNav`——`admin.html` 已經有 `#adminNav` 在用了。
⚠️ 只有一項可去時整條不顯示（`renderPageNav()`）：一般管理者目前只有「班表列表」，
畫一條只有一顆、按了還停在原地的導覽列，使用者會以為壞了。2d 加「新增」之後就自然有兩項。

### 修掉「手機上詳細收不起來」✅（v2.6）

使用者回報：手機上每一筆的「詳細」永遠是展開的，點「收合」沒有反應；電腦上正常。

**根因：作者的 `display` 規則蓋過了瀏覽器內建的 `[hidden]`。**

程式是用 `row.hidden = !row.hidden` 收合的（`js/admin-list.js`）。
而瀏覽器內建的 `[hidden] { display: none }` 是 **UA 規則**——
任何一條作者寫的 `display` 都贏得過它。卡片模式那一段正好有：

```css
@media screen and (max-width: 760px) {
  .dtable, .dtable tbody, .dtable tr, .dtable td { display: block; }
}
```

於是 `hidden` 在手機上完全沒有效果。桌機沒有這條作者規則，所以正常——
**在電腦上測永遠測不出來**，這是它從 v1.8 活到現在的原因。

修法是加第 4 條防禦規則（`css/style.css` 最上面）：

```css
[hidden] { display: none !important; }
```

⚠️ 這裡用 `!important` 是對的：`hidden` 是「這個東西現在不該存在」的**語意宣告**，
沒有任何版面理由可以推翻它。整個 normalize 類的 reset 都是這樣寫的。

⚠️ **這個 bug 逃過了 v2.4 的自動版面檢查**，因為那支只驗「沒有橫向捲動 /
點擊目標夠大 / 沒有元素超出畫面」——它從來沒有**按下按鈕**。
新增 `test-detail.js`：手機與桌機各驗「一開始收合 → 點開 → 再點收合」，
而且是量 `getBoundingClientRect().height`，不是只看 `hidden` 屬性
（這個 bug 的特徵就是 `hidden=true` 但高度 > 0）。

### 帳號規則與載入速度 ✅（v2.5）

**帳號不再限定電子郵件**。規則改成英數 ＋ `.` `_` `-` `@`，長度 3~64
（`gas/Admins.js` 的 `looksLikeAccount_`）。所以 `ga2`、`ken.wang` 都可以。
登入端本來就沒有擋格式，只有建立端有。

⚠️ **這個放寬有一個必要的配套，少了它會開一個安靜的洞。**
「忘記密碼」的收件人是這樣決定的（`gas/Auth.js`）：

```js
var to = str_(admin.email_notif) || str_(admin.account);
```

帳號還是 email 的年代，通知信箱空著沒關係。現在帳號可以是 `ga2`，兩個都空的話
`MailApp.sendEmail('ga2', …)` 會丟例外，而那個呼叫**包在 try/catch 裡**——
畫面說「已寄出」，信永遠不會到，也沒有任何錯誤訊息。

兩道防線：

| 在哪裡 | 擋什麼 |
|---|---|
| `adminOpCreate_` 的 `EMAIL_NOTIF_REQUIRED` | 建立帳號的當下就要求填通知信箱 |
| `requestPasswordReset` 寄信前先檢查收件人 | 超管**可以直接在 Sheet 上把通知信箱清掉**，繞過第一道。這一道讓日誌說得出真正的原因（「帳號不是 email，而 email_notif 是空的」），而不是 MailApp 的 `Invalid email` |

⚠️ 第二道之所以要「先檢查再寄」而不是靠 catch，是因為**日誌訊息的品質**。
階段 4 的每日系統信會把 LOG 送到管理者眼前，訊息說得越準越有用。

**載入速度：班表列表的兩趟 API 改成同時發。**

```js
const profile = await requireLogin();   // 舊：3~8 秒
if (!profile) return;
document.getElementById('content').hidden = false;   // 畫面到這裡才出現
loadData();                              // 再 3~8 秒
```

兩件事其實**互不相依**——查資料本身就會驗 token（後端的 `withAuth`），
`requireLogin` 只是為了拿姓名／角色並在失效時導頁。改成同時發之後，
總時間從兩者的**總和**變成**最大值**。

另外把「準備篩選條件」搬到發 API 之前（`loadData()` 要讀 `#fFrom`／`#fTo`），
畫面也不再等驗證回來才顯示。

實測（每支 API 模擬 3 秒延遲）：

| | 改之前 | 改之後 |
|---|---|---|
| 畫面出現 | 3000 ms | **144 ms** |
| 資料出現 | 6000 ms＋ | **3469 ms** |
| 兩趟相隔 | 3000 ms（串接） | **0 ms（同時）** |

⚠️ 這只解決 Apps Script 那一段。使用者反映「每個頁面都慢」，
而首頁與查詢頁**一次 API 都沒打**（實測本機渲染 149ms／104ms、下載 57KB／73KB），
所以若那兩頁也慢，原因在網路或 GitHub Pages，要另外查。

**班表列表不再顯示編號與分頁位置**（使用者要求）。資料沒有拿掉，只是不畫出來——
2d 的修改／刪除要靠 `it.id` 認出是哪一筆（設計約定：一律用 id 查找，不可用列號），
修改畫面上會顯示編號。

⚠️ 一個原本以為要修、查證後發現不必修的：管理端的錯誤代碼**早就翻譯好了**，
走的是 `tAccountError`（`js/admin-accounts.js`）→ `tAdminError`（`js/admin-session.js`）
這條鏈，不經過 `js/i18n.js` 的 `tError`（那一支只服務使用者端的 `query.js`）。
真正缺的只有 v2.5 新增的兩個代碼。**不要在 tError 裡再翻一份**——
同一個代碼兩份翻譯，改了一邊忘了另一邊，使用者會看到兩種說法而且查不出原因。

#### 兩份名冊的重複標示，刻意用兩種完全不同的做法

| 名冊 | 抓什麼 | 顏色 | 怎麼做 |
|---|---|---|---|
| `DAFTAR PERSONEL` | **中文姓名**重複 | 🟡 整列淡黃 | **Google Sheet 條件式格式** |
| `JADWAL PENERBANGAN` | **航班號**撞號 | 🔴 該格紅底 ＋ 註解 | 程式寫入背景色 |

**人員名冊為什麼改用條件式格式**（這是專案裡第一個刻意「不寫程式」的功能）：

程式寫背景色的話，顏色是**存進儲存格的屬性**，所以每次資料變動都得重算並把
「不再重複的」清掉。麻煩的是「什麼時候重算」——要靠 `onEdit`（打字）、
`onSheetChange`（插入／刪除列，**安裝型觸發器**）、`onOpen`（開檔案）三條路去接。
其中 `onSheetChange` 有三種**靜默失效**的方式：忘了跑 `installTriggers()`、
換人安裝、Google 因授權變動停用它。失效的樣子是「刪掉重複的那一列之後，
另一列的顏色一直留著」——使用者會去找一個已經解決的問題。

條件式格式是 **Google 每次自己重新計算**的結果，不是存進去的格式：

| | 程式寫背景色 | 條件式格式 |
|---|---|---|
| 何時變色 | 要等觸發器 | **打完字立刻** |
| 刪掉重複的之後 | 靠程式重算清除 | **自動消失** |
| 觸發器失效 | 靜默壞掉 | 不受影響（不用觸發器） |
| Apps Script 配額 | 每次都花 | **零** |
| 要維護的程式碼 | 約 150 行 | 一次設定，之後 **0 行** |
| 註解 | 有 | **沒有** |

代價是沒有註解。人員名冊的目的是「整理時一眼看出來」，看得到就夠了；
航班名冊需要在註解裡指出「撞號的是第幾列」，所以留在程式那一邊。

**幾個實作上的要點：**

- ⚠️ 用**黃色不用紅色**。中文同名同姓在華人圈很常見，那可能真的是兩個不同的人。
  紅色要留給「確定有問題」，濫用會讓紅色失去意義（`MARK_DUPE_NAME_BG` / `MARK_DUP_BG`）。
- ⚠️ 公式先擋掉空白：`=AND($D2<>""; COUNTIF($D$2:$D; $D2)>1)`。
  中文姓名**可以空白**（規格書：眷屬／訪客可空白），不擋的話整張表都會變黃。
- ⚠️ 範圍與 `COUNTIF` 都寫成**開放式**（`A2:J`、`$D$2:$D`），名冊加到幾百人
  都自動涵蓋，不必有人記得回來調範圍。
- ⚠️ **公式的參數分隔符號跟地區設定有關**：`en_US` 用逗號、`id_ID` 用**分號**。
  寫死逗號的話公式直接無效而且不報錯。用 `formulaSep_()` 實際量一次
  （見 `docs/部署筆記.md` 的踩坑紀錄）。
- 套用後立刻 `SpreadsheetApp.flush()`：Google **延後驗證公式**，不 flush 的話
  錯誤會等到下一次寫入才爆，堆疊指到不相干的地方。
- 只清掉「套用在同一個範圍」的舊規則，不整張砍掉重來——使用者自己加的
  條件式格式（例如把停用的人標灰）不可以被洗掉。
- 重新套用：🛫 選單 →「重設名冊的重複標示」（平常不必按，設定一次就永遠有效）。

#### 移除一個欄位（v2.3），比想像中危險

拿掉人員名冊的「EMAIL NOTIFIKASI 通知信箱」。這一欄從上線到移除為止
**沒有任何程式讀過或寫過**（`readRoster_()` 只讀 email / 姓名 / 中文名 / 部門 /
廠別 / 房號 / 手機 七欄），而系統信本來就只寄給管理者與超管，不寄給個別人員。
留著一個永遠空白的欄位，只會讓管理者每次維護名冊時停下來想「這欄到底要不要填」。

⚠️ 別跟 `ADMIN_COLUMNS` 的 `email_notif` 搞混——**那一欄正在用**，
是「忘記密碼」時臨時密碼的收件地址（`gas/Auth.js`），不可以拿掉。

**真正的風險不是刪錯欄，是刪對了卻安靜壞掉。** 兩個原因：

**1. 被拿掉的那一欄，就在 `AKTIF 啟用` 的左邊。**
`readRoster_()` 與 `onEditPerson_()` 原本用 `PERSON_COLUMNS` 的**定義順序**
對應欄位。所以只要「程式的定義」和「Sheet 上的實際欄位」有一邊先變、另一邊還沒變，
整排就位移一欄：

```
c.aktif 指到空白欄 → CODE_OF[''] 不等於 'N'
  → 停用判斷失效 → 已停用的人全部重新出現在管理者的候選清單裡
```

而且**不論先改程式還是先刪欄，中間那段時間都會壞**，畫面上完全看不出來。
（實測過：把 `readRoster_()` 換回舊寫法，那筆 `Tidak 否` 的資料確實被帶回來了。）

**解法：全部改用 `buildColumnMap_()`**（照表頭名稱找欄）。改完之後
「先改程式還是先刪欄」這個順序問題就不存在了。順手把 `onEditFlight_()`
也一起改掉——同一類問題，`gas/Utils.js` 的檔頭本來就寫了不可以用定義順序。

**2. `applyStructure_()` 的表頭是「按位置」寫的。**
程式定義少一欄、Sheet 上那一欄還在的話，`setupSheet()` 會把
`AKTIF 啟用` 這個標題**蓋到舊的通知信箱欄上**，於是表上出現兩個
`AKTIF 啟用`，`buildColumnMap_()` 取到左邊那個（空的）——又回到同一個症狀。

**解法：`dropRetiredPersonColumns_()`**，放在 `setupSheet()` 的最前面。
它**按表頭名稱**刪欄，而且有兩道保險：只刪列在 `RETIRED_PERSON_HEADERS`
名單上的欄、而且只刪目前定義裡沒有的欄。所以管理者自己在右邊加的欄位不會被掃掉。
由右往左刪（由左往右刪的話，刪一欄之後右邊全部左移，後面的欄號整排錯位）。

**給管理者的操作**：🛫 選單 →「**整理人員名冊欄位（移除退役欄）**」，
一鍵完成「刪欄 ＋ 重套整列標黃（範圍從 `A2:K` 變 `A2:J`）」。
兩件事必須一起做：只刪欄不重套，最右邊會多黃一欄。
⚠️ 刻意不叫人自己在 Sheet 上右鍵刪欄——程式按名稱找欄不可能刪錯，
手動刪錯一格就是真的資料不見了。

⚠️ `tools/convert.py` 產出的 `人員名冊_初版.csv` 也跟著改成 10 欄。
匯入是「照位置貼」的，CSV 多一欄少一欄整排就位移。

### 階段 2d 之內 — 一次帶出同行眷屬（使用者已確認方向，2026-09-03）

**⚠️ 開新對話時請主動提醒使用者這一項。** 這是他明確要求「到時候提醒我一次」的工作。

**要解決什麼**：一個 email 底下有多位（員工＋眷屬，設計約定第 6 條）時，
在週分頁打那個 email，姓名／中文名／房號會**全部留白**——因為三個人的值都不同，
`agreedValue_()` 填哪一個都是錯的。使用者要的是「一次把全家帶出來，不跟的再刪掉」。

**做法：一支與呼叫端無關的核心函式，兩個包裝。**

| 包裝 | 給誰 | 狀態 |
|---|---|---|
| app 新增頁面的**勾選介面**（☑ 誰要一起去 → 只寫該寫的列） | 一般管理者 | **要做** |
| 🛫 選單「加入同行眷屬」（Sheet 上按一下插入 N 列） | 超管 | **建議不做**，見下 |

⚠️ Sheet 選單版原本的理由是「2d 還沒做，中間先頂著」。既然 2d 緊接著就要做，
多寫一個包裝的報酬變低了。**勾選介面還比它好**：Sheet 上做不到跳選單，只能
「全部長出來、不跟的自己刪」；app 上可以先問要帶誰，**多餘的列從頭到尾沒被寫進去過**，
也就不必刪——連帶避開了下面那兩個決策的爭議。

核心負責：從員工那列**複製**日期／接送／航班號／ETD-ETA／出廠時間／上車地點（同班機同車），
各自帶入姓名／中文名／**各自的房號**／手機，編 `booking_id`、填 `STATUS`、
**填同一個 `group_id`**（此欄早已建好並貫通 `_INDEX`／查詢 API／班表列表，填了就能用）。

順便一起做：**email 與姓名同時填寫時，用姓名把候選縮小到一位**。
現在 `autoFillRows_()` 是 email 優先，email 一旦對到多人就不會再用 NAME 過濾，
於是「打了共用 email 又手打眷屬姓名」時，房號與中文名仍然留白。

⚠️ **不要做成「打 email 就自動長出下一列」**（評估過，已否決）。三個理由：
1. `onEdit` 每動一格就跑一次 → 管理者刪掉不跟的那一列後，下次編輯同一列時它會**長回來**，
   使用者看到的是「刪不掉」。這個坑本專案踩過（見 `gas/AutoFill.js` FILLABLE_FIELDS 的註解）。
   要避開得再加一個「已展開過」的標記欄，又是一次結構變更。
2. 打 email 的當下日期與航班通常還沒填，長出來的列是空的，省不了多少工。
3. 一般管理者最終走 app，不進 Sheet；加固 `onEdit` 是投資在正被取代的路徑上。

⚠️ **2d 開工前要先定兩個決策**（自動長出的列讓這兩件事撞在一起）：
1. app 上的「刪除」是實際刪列，還是把 `STATUS` 設成「已取消」？
   兩種情況在畫面上長得一樣，但意義完全不同：**真的取消行程**要留紀錄（已取消），
   **系統長出來但沒人確認過的列**該實際刪掉（什麼都沒發生，留一筆已取消會汙染統計）。
2. 一般管理者該不該有實際刪列的權限，還是只留給超管？

  → 用**勾選介面**可以把這個問題整個繞開：沒寫進去就不必刪，一般管理者只需要「取消」。

## 目前安裝的 4 個觸發器

| 函式 | 時機 | 用途 |
|---|---|---|
| `rebuildIndexIfDirty` | 每 5 分鐘 | 有人改過才重建 `_INDEX`（無條件重建會超出每日配額） |
| `markPastAsDone` | 每小時 | 時間過了的「已排定」改成「已完成」 |
| `ensureUpcomingWeekSheets` | 每天 03:00 | 建好從今天起半年份的週分頁 |
| `onSheetChange` | 結構變動時 | 接住插入列／刪除列（**`onEdit` 對這些不觸發**），重建索引 ＋ 重算兩份名冊的重複標記 |

⚠️ 新增觸發器之後**一定要重跑 `installTriggers()`**，`clasp push` 不會讓 Google 的鬧鐘自己出現。

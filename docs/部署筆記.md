### ⚠️ 第 26 步第一次一定會失敗一次

Apps Script 靠掃描程式碼推算需要哪些權限。剛推上新程式碼時它可能還在用舊的權限清單，
於是「授權畫面按過了，功能照樣被擋」。**再執行一次就好**——第二次的授權畫面才會包含新權限。

⚠️ **新增排程之後一定要重跑 `installTriggers()`。**
`clasp push` 只是把程式碼推上去，Google 的鬧鐘不會自己出現——新排程就這樣安靜地不存在。
`installTriggers()` 會先清光再重裝，重複執行是安全的。

## 日常更新流程

### 一般情況：一個指令搞定

```bash
node tools/release.js 0.3 "這次改了什麼"
```

它會依序做完：改版本號（所有 HTML 的 `?v=` ＋ `js/config.js` ＋ `gas/Config.js`）→
跑 `tools/check.js` → `git add/commit/push` → `clasp push` → `clasp redeploy`。
**任何一步失敗就整個停下來**，不會推出半套。

想先看它要做什麼：

```bash
node tools/release.js 0.3 "說明" --dry-run
```

只想檢查、不發布：

```bash
node tools/check.js
```

⚠️ **後端沒有改動時會自動略過 `clasp push` 與 `redeploy`**，只推 GitHub。
⚠️ **這次如果新增了排程，發布後要回 Apps Script 執行 `installTriggers()`**——
`clasp push` 只是把程式碼推上去，Google 的鬧鐘不會自己出現。

---

### 以下是手動流程（`release.js` 壞掉時的備案）

### 只改前端（HTML / CSS / JS）

改了 CSS 或 JS 的話，**先把所有 HTML 的 `?v=` 版本號往上加**
（KANTIN 設計約定第 5 條：GitHub Pages 快取 10 分鐘，漏改會讓使用者拿到舊的 JS 配新的 API，
畫面會用「錯誤的方式」壞掉）。

```bash
git add . && git commit -m "說明" && git push
```

### 改後端（`gas/`）

```bash
cat gas/*.js > tmp-all.js && node --check tmp-all.js && rm tmp-all.js
```

```bash
clasp.cmd push -f
```

```bash
clasp.cmd redeploy <部署ID> -d "說明"
```

⚠️ 串接檢查不要寫成 `cat gas/Config.js gas/*.js`——`gas/*.js` 已經包含前者，
串兩次必然報 `Identifier has already been declared`，看起來像程式有錯，其實是指令本身的問題。

`node --check` 抓得到重複的 `const`，**但抓不到重複的 `function`**（重複的函式宣告在 JS 裡合法，
後面那個會無聲蓋掉前面那個）。新增函式時順手跑：

```bash
grep -oh "^function [a-zA-Z0-9_]*" gas/*.js | sort | uniq -d
```

## 換電腦

Windows 公司電腦 ↔ macOS 私人電腦，透過 GitHub 同步。

```bash
git pull
```

| 項目 | 說明 |
|---|---|
| 指令前綴 | macOS 直接用 `clasp` / `npm`；Windows 要用 `clasp.cmd` / `npm.cmd` |
| clasp 憑證 | 不在專案裡，換電腦要重新 `clasp login`。**只有要改後端才需要** |
| 測試檔路徑 | 一律用 `path.join(__dirname, '..')`，不可寫死 `D:/Claude/Airport` |

**不會跟著 git 走的東西**（換電腦時不必也不能帶）：

- clasp 登入憑證（`~/.clasprc.json`）→ 重新 `clasp login`

- `data/` 底下的 CSV → 有個資，不進 git。需要的話重跑 `python tools/convert.py`

## 踩坑紀錄

> 遇到新的坑就往下加，寫清楚「看到什麼現象」和「真正的原因」。

| 日期 | 現象 | 原因與解法 |
|---|---|---|
| 2026-09-02 | `airport.xls` 用 Python 讀出來中文是亂碼 | 不是檔案壞掉，是 Windows 主控台編碼。指令前面加 `PYTHONIOENCODING=utf-8` 就正常 |
| 2026-09-02 | 9 月的分頁裡有兩筆 3 月的資料 | 有人寫 `03/09 20:00`（想表達 9 月 3 日），Excel 照 mm/dd 讀成 3 月 9 日。**根因是那一欄不是純文字格式**。新 Sheet 的出廠時間欄一律設純文字 |
| 2026-09-02 | `rebuildIndex()` 單次要 19.4 秒（14 個週分頁） | 排程若無條件每 5 分鐘跑一次 = 288 次 × 19.4 秒 = **一天 93 分鐘，已經超過一般 Google 帳號 90 分鐘／天的排程配額**；一年後 52 個週分頁時單次 60~70 秒，一天要 5 小時。超額的樣子是「排程在中午被停掉、下午的資料都沒更新」，**而且完全沒有錯誤訊息**。解法：`onEdit` 立旗標，排程只在有人改過時才重建，另加「超過 6 小時強制重建一次」當保險 |
| 2026-09-02 | 貼進 Apps Script 報 `SyntaxError: Invalid or unexpected token`，指到的那一行看起來完全正常 | 字串字面值裡有一個 **NUL 位元組**（本來應該是空格）。編輯器不顯示這種字元，肉眼絕對找不到。而且 `node --check` **不會報錯**（Node 的 V8 容忍它），本機檢查是全綠的。解法：檢查流程加上控制字元掃描，見 `CLAUDE.md` 的「修改後端的標準流程」 |
| 2026-09-02 | `setupSheet()` 報 `data validation rule argument is invalid`，堆疊指到 `protectHeader_` | **兩個坑疊在一起**。① Google 試算表的公式參數分隔符號跟地區設定有關：`en_US` 用逗號、`id_ID`（小數點是逗號）用**分號**。而 `setupSheet()` 第一件事就是把地區設成 `id_ID`，寫死逗號的驗證公式必然無效。② Google **延後驗證公式**，錯誤要等下一次寫入才爆，所以堆疊指到後面幾行的 `protectHeader_`，看起來像保護表頭壞掉。解法：`formulaSep_()` 寫 1.5 到暫存分頁量出真正的分隔符號；套用公式規則後立刻 `SpreadsheetApp.flush()`，錯誤才會在正確的那一行被接住 |
